# char-forge — 汉字笔画数据生成管线

为 `data/stroke-bundle.js` 批量创造缺失汉字的笔画数据（SVG 路径 + medians）。
核心方法：**donor 移植法** —— 从 bundle 已有字中提取同部件笔画，平移/微缩到目标位置。

## 为什么不用 CDN 部件拼接？

hanzi-writer-data（CDN）的部件来自独立字（如 standalone `日` = 486×722，横粗 83）。
缩到合体字里（如 但 的 日 = 466×401）时若按比例缩放，横粗会变成 ~46，
而字体真实设计是 65-71 —— **字体对合体部件做了加粗补偿，线性缩放永远偏细**。

bundle 里 9605 个字本身就是字体设计的成果：`但` 的 `亻/日/一`、`夜` 的 `亠`
已经是"正确尺寸+正确粗细"的现成部件。直接移植，粗细自动达标。

## 笔画粗细规范（自动测量，weight_norms.json）

thickness = 笔画 bbox 短边（仅横/竖类，斜笔不检查）：

| 横 len→ | 200 | 300 | 400 | 500 | 600 | 700 | 800 |
|---------|-----|-----|-----|-----|-----|-----|-----|
| thick   | 63  | 92  | 115 | 126 | 128 | 137 | 149 |

| 竖 len→ | 200 | 300 | 400 | 500 |
|---------|-----|-----|-----|-----|
| thick   | 92  | 99  | 112 | 115 |

build 时自动校验：thick < norm×0.75 → `THIN!`（阻断 install）。

## 命令

```powershell
node forge.js norm                    # 重建粗细规范表（bundle 变化后跑一次）
node forge.js donors 日 400 300       # 找包含"日"的字，列出笔画范围+bbox（≥400×300）
node forge.js build configs\X.json   # 生成 + 校验 + 预览（out\）
node forge.js install configs\X.json # build + 备份 + 替换 + 验证（粗细不达标会拒绝）
```

## 配置格式（configs\亱.json）

```jsonc
{
  "char": "亱",
  "strokes": [
    // 纯平移（首选：donor 尺寸合适，粗细 100% 保留）
    { "name": "日竖", "donor": "但", "index": 2, "t": { "tx": 14, "ty": -106 } },
    // 单笔画 fit（把该笔画 bbox 映射到区域；会改变粗细，配合 widenX/widenY 校正）
    { "name": "亠横", "donor": "夜", "index": 1, "fit": { "x0":110, "x1":910, "y0":646, "y1":809 } },
    // 分组 fit（多笔部件共享变换，按组合 bbox 映射 —— 亻的两笔一起变换）
    { "name": "亻撇", "donor": "但", "index": 0, "group": "ren", "fit": { "x0":75, "x1":335, "y0":30, "y1":585 } },
    { "name": "亻竖", "donor": "但", "index": 1, "group": "ren", "fit": { "…": "…" }, "widenX": 95 }
  ]
}
```

- 坐标系：1024×1024，**y 轴向上**（y=900 顶，y=100 底）
- `widenX: N`：竖类笔画增粗到 N（沿 x 扩展，锚定左缘）
- `widenY: N`：横类笔画增粗到 N（沿 y 扩展，锚定下缘）
- 笔画顺序必须与 wubi `r` 数组的字根分组一致（着色依赖它）

## 单字工作流

1. **拆字**：确定 r 数组与笔顺（参考 wubi_xsj.js / 字形）
2. **找 donor**：`node forge.js donors <部件> <最小宽> <最小高>`，
   优先选**同族字**（如 亱 用 夜/但）——部件风格、粗细最接近
3. **写配置**：donor 尺寸合适 → 纯 `t` 平移；差得多 → `fit`/`groupFit` + `widen`
4. **build**：看报告（粗细、bbox、整字 aspect≈0.95-1.05）+ 浏览器开预览 HTML
5. **install**：自动备份 `stroke-bundle.js.bak_<unicode>`，替换后验证
6. **页面验证**：Ctrl+F5 强刷，输入字查动画/编码/着色

## 批量策略（1.7 万字）

- 拆分来源：wubi 三表的 `r` 数组（新世纪版最全，含 comp 部件级拆分）；
  缺失的用 `⿰⿱⿲⿳⿴⿵⿶⿷⿸⿹⿺⿻` IDS 手工补
- 布局模板：⿰ 左右（窄部件 30-38% 宽）、⿱ 上下（顶部部件 ~30% 高）、
  ⿲ 三分左右、包围结构（外框 60-65% 宽，内部收框内）——先做常用 10 个模板
- donor 优先级：同族字 > 同部件尺寸接近的字 > CDN standalone（最后手段+加粗校正）
- 每批 50-100 字：批量 build 出报告 → 人工只看 THIN/FAIL 和预览图 → 批量 install

## 已知限制

- 新增字（bundle 中完全没有的）暂不支持 insert，只支持替换（需手工加键）
- 斜笔（撇捺）无粗细校验，靠 donor 选择保证
- `install` 的防呆检查（粗细/笔画数/逗号）不要为赶进度跳过
